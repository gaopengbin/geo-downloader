# 瓦片请求节奏与失败恢复

桌面端和 CLI 共用 `src-tauri/src/downloader.rs`、`tile_requests.rs` 和
`tianditu_tokens.rs`。自动更新安装包下载不使用此队列。

## 请求节奏

- 高德 `appmaptile`：最多 4 个在途请求，初始相邻启动间隔 62.5 ms。
- 天地图（本地候选优化）：每个 Key、每项瓦片服务初始 16 次/秒、4 个在途请求，正常时每稳定 2 秒且成功至少 16 张，增加 4 次/秒和 1 个在途名额，最高 64 次/秒、16 个在途请求。任务配置的并发仍是任务自身的上限。
- 同一 Key 和服务的不同子域、任务、重试、下载前核验及图源测试共用预算；底图、注记、不同 Key 分别记录。按实际发送的 Key（包括备用 Key）选择预算；排队时 Key 变化则重新排队。
- 天地图路径式和查询式 WMTS 服务名统一归一化，不因切换子域、坐标、参数顺序而获得额外预算。注册表仅存 Key 和服务的摘要；最多保留 128 个独立预算，更多组合固定共用额外预算，不驱逐冷却中的预算。
- 缓存命中不占预算。普通地图在线预览不经过下载队列。

这些是 GeoD 的客户端策略，不是服务方公布的配额或可用性保证。
遇到 429/503 时，等待服务端 `Retry-After`，缺省使用指数退避加随机抖动（第 n 次在半个至一个退避上限间随机选择，上限从 1 秒增长至 32 秒）；
即使服务端返回 0，也至少等待 250 ms，避免立即重复请求。
服务端要求等待超过 60 秒，或重试预算用尽时，保留任务数据并返回明确限流错误。
等待在网络请求超时之外进行；退避不占在途名额，暂停/取消可由上层任务中断。

限流时将速率及在途名额减半，最低每秒 1 次、1 个在途请求。连续限流波次使用服务级指数冷却，避免每换一张瓦片就把退避重置为 1 秒；高德最高保持原初始节奏。
同一波并发的旧限流回复共同延长等待，不重复叠加降速；限流前已发出的成功回复不能提前认定恢复。
发生过限流的预算在连续至少 16 次新成功、至少 5 秒稳定后，每次只增加每秒 1 次和 1 个在途名额，避免快速恢复到刚才失败的速率；同进程后续任务沿用已学习的状态，不从初始速率重新试探。
唤醒时重新检查发送时刻，不积攒可突发使用的请求额度，避免冷却或系统卡顿结束后一批请求同时发送。取消排队不预占未来发送时刻；释放请求名额会唤醒等待者。
下载进度会显示“服务限流，自动冷却约 N 秒后继续下载”；长等待或持续拒绝导致停止时仍保留已有数据，429 不标记 Key 失效。

3.6.25 已发布包仍使用原来的 4 在途、125 ms 初始间隔。上述天地图提速策略为本地候选代码，尚未发布。

## Key 和错误分类

- 天地图 429 保留当前 Key，不切换、不标记失效。
- 天地图 401/403 才尝试用户配置的备用 Key；全部被拒绝时保留最后 HTTP 状态，
  提示核对认证、权限与服务状态，不认定额度耗尽。
- 高德及其他图源 401/403 明确停止，保留任务数据，不自动修改代理、地址或请求身份。
- 各图源 429/503 使用有界等待重试，持续失败返回 `TILE_RATE_LIMITED`。
- 本地候选在任务仍有可用瓦片、最近 90 秒有有效进展时，将孤立的单片限流交给现有补试队列，不因一张片耗尽单次重试就终止整项大任务。空预检、无进展或服务明确要求超过 60 秒等待仍会停止并保留进度。
- 补试成功的瓦片写回统一的 `x/y.png` 工作路径，恢复任务时可直接复用；未补齐的瓦片继续按既有缺块状态报告，不算完整成功。
- 错误响应最多读取 4 KiB、250 ms；仅输出最多 12 位的数字 `code`/`infocode`。
  不输出原始响应、完整 URL、Key 或自由文本，也不把服务错误码擅自解释为日额度耗尽。
- 错误响应不会作为图片写入。成功响应仍须通过现有瓦片校验后才落盘。

## 验证

```powershell
rtk cargo test --manifest-path src-tauri/Cargo.toml --lib -- --test-threads=1
rtk cargo test --manifest-path crates/geod-core/Cargo.toml --lib -- --test-threads=1
rtk cargo test --manifest-path crates/geod-cli/Cargo.toml -- --test-threads=1
```

回归使用回环服务器和真实 HTTP 客户端：分别为高德、天地图返回一次 429，
等待后对同一请求返回有效 PNG，检查请求内容/Key 未改变、等待时间、最终文件以及 Key 状态。
另外覆盖跨任务/子域发送节奏、排队期间增加冷却、取消释放名额、持续 429、
长 `Retry-After`、401/403、错误码脱敏和旧的下载/缓存回归。
显式运行约两分钟的 2048 张回环传输验收：

```powershell
rtk cargo test --manifest-path src-tauri/Cargo.toml --lib downloader::scheduler_tests -- --include-ignored --nocapture --test-threads=1
```

该验收启动两个不同子域的任务，共用同一 Key 和服务，中途注入一次 429；检查平滑发送、冷却时间、两个任务均自然完成、2048 个文件逐字节一致，以及恢复任务零网络请求。
测试套件按单线程运行，避免共享预算的测试清理互相干扰。

本地受控恢复测试不能证明某个用户网络或 Key 已恢复；服务端持续拒绝仍需实际状态码
与错误码定位。本修复不改变外部服务的权限或配额。
