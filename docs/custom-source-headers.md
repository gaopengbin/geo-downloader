# 自定义图源请求头

在「图源管理 → 自定义图源 → 手动新增 / 编辑」中添加请求头名称和值。也可在「内置覆盖」中给已有图源配置，或在「智能解析」前填写。

常见用法：

| 名称 | 值的格式 |
| --- | --- |
| Authorization | `Bearer <你的 Token>` |
| X-API-Key | 服务商提供的 Key |
| Cookie | `session=…; other=…` |
| Referer | 服务商要求的来源页面地址 |
| User-Agent | 服务商要求的客户端标识 |

点击「测试图源（含请求头）」验证样例瓦片后保存。地图预览与下载使用该图源的配置；修改后会重建当前预览图层。样例测试通过仅代表该样例可用，不代表所有区域或层级有数据。

请求头值默认隐藏，可以点击眼睛图标查看。名称不区分大小写，同名项不能重复；值不能包含换行或控制字符。Host、Content-Length 等由 HTTP 客户端管理。

配置保存在本机的 `settings.json` 中，未额外加密。不要分享包含 Token / Cookie 的配置文件。请求头不会拼进瓦片 URL，不会写入瓦片元信息，日志的 Debug 输出也不会显示其值。

认证请求由桌面端本地 HTTP 客户端发出，覆盖光栅与 MVT 预览、图源测试和下载。浏览器开发预览无法代替桌面端的任意请求头能力。同站重定向保留配置；跨站重定向会停止，避免把凭证发送到其他域名或端口。带请求头的下载使用独立缓存标识，修改地址或凭证不会命中旧的共享瓦片缓存。

适用于已有 Token、Cookie 和来源校验。凭证到期后需自行更新；验证码、自动登录和动态签名需要相应图源适配。

## 验证

- `rtk proxy cargo test --manifest-path src-tauri/Cargo.toml --lib headers -- --test-threads=1`：本地认证 HTTP 服务，覆盖样例测试、预览、下载、同站/跨站跳转、普通/压缩 MVT、配置保存与清除。
- `rtk proxy npm test`（`frontend` 目录）：请求头解析及前端回归。
- `frontend/tests/source-headers.html`：真实图源管理组件和瓦片图层的浏览器交互测试，使用隔离的模拟 Tauri 接口，不修改用户配置；与上述真实 HTTP 测试分开。
