# 瓦片请求节奏与失败恢复

桌面端和 CLI 共用 `src-tauri/src/downloader.rs`、`tile_requests.rs` 和
`tianditu_tokens.rs`。自动更新安装包下载不使用此队列。

## 请求节奏

- 高德 `appmaptile`：最多 4 个在途请求，初始相邻启动间隔 62.5 ms。
- 天地图：最多 4 个在途请求，初始相邻启动间隔 125 ms。
- 同一提供方的不同子域、任务、底图、注记、重试、下载前核验及图源测试共用预算。
- 缓存命中不占预算。普通地图在线预览不经过下载队列。

这些是 GeoD 的客户端策略，不是服务方公布的配额或可用性保证。
遇到 429/503 时，等待服务端 `Retry-After`，缺省使用 1、2、4…秒的有界退避；
即使服务端返回 0，也至少等待 250 ms，避免立即重复请求。
服务端要求等待超过 60 秒，或重试预算用尽时，保留任务数据并返回明确限流错误。
等待在网络请求超时之外进行；退避不占在途名额，暂停/取消可由上层任务中断。

高德/天地图预算会在限流后将启动间隔翻倍（最高 1 秒），并推迟已经排队的请求。
恢复后，每连续 16 次成功将间隔缩短为原来的 3/4，最低为初始间隔。
唤醒时重新检查发送时刻，避免等待结束后一批线程同时发送。

## Key 和错误分类

- 天地图 429 保留当前 Key，不切换、不标记失效。
- 天地图 401/403 才尝试用户配置的备用 Key；全部被拒绝时保留最后 HTTP 状态，
  提示核对认证、权限与服务状态，不认定额度耗尽。
- 高德及其他图源 401/403 明确停止，保留任务数据，不自动修改代理、地址或请求身份。
- 各图源 429/503 使用有界等待重试，持续失败返回 `TILE_RATE_LIMITED`。
- 错误响应最多读取 4 KiB、250 ms；仅输出最多 12 位的数字 `code`/`infocode`。
  不输出原始响应、完整 URL、Key 或自由文本，也不把服务错误码擅自解释为日额度耗尽。
- 错误响应不会作为图片写入。成功响应仍须通过现有瓦片校验后才落盘。

## 验证

```powershell
rtk cargo test --manifest-path src-tauri/Cargo.toml --lib -- --test-threads=1
rtk cargo test --manifest-path crates/geod-core/Cargo.toml --lib -- --test-threads=1
rtk cargo test --manifest-path crates/geod-cli/Cargo.toml -- --test-threads=1
```

回归使用回环服务器和真实 HTTP 客户端：分别为高德、天地图返回一次 429，
等待后对同一请求返回有效 PNG，检查请求内容/Key 未改变、等待时间、最终文件以及 Key 状态。
另外覆盖跨任务/子域发送节奏、排队期间增加冷却、取消释放名额、持续 429、
长 `Retry-After`、401/403、错误码脱敏和旧的下载/缓存回归。
测试套件按单线程运行，避免共享预算的测试清理互相干扰。

本地受控恢复测试不能证明某个用户网络或 Key 已恢复；服务端持续拒绝仍需实际状态码
与错误码定位。本修复不改变外部服务的权限或配额。
