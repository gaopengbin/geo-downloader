# Windows 应用内更新的自动换源

更新器根据当前发布清单的 Windows 安装包确定目标版本、文件大小和 SHA-256。
国内镜像与 GitHub 官方 Release 是同一版本的两个下载候选；优先使用清单选中的
地址，连接失败、HTTP 错误、断流、持续低速或校验失败后，自动尝试另一条源。
所有源都不可用时，回到应用内重试，不自动打开浏览器要求用户手动下载安装包。

默认网络边界：连接超时 5 秒，等待响应头最多 8 秒，连续无数据最多 5 秒。
按约 8 秒窗口观察吞吐量，持续低于 64 KiB/s 时换源；初始快速传输后变慢也会
被后续窗口检测到。单条源总时长最多 180 秒。两条候选各尝试一次，避免无限重试。
这些是客户端容错策略，不是服务器提供的带宽承诺。

切换时删除未完成的临时包，从零下载另一条源，避免把不兼容的响应直接拼接。
界面明确提示自动换源/重新下载，并显示当前来源和速度。下载进度最高到 99%，
字节数、SHA-256 和 Windows 可执行文件标记全部验证通过后才显示 100% 并启动安装。
失败、HTML 错误页、不完整文件和错误版本都不会作为安装程序运行。

更新使用独立随机临时目录，并阻止重复并发启动。网络仍使用现有系统代理设置；
不修改全局代理。重定向保留 HTTPS 且限定官方分发主机。安装程序启动成功后才退出
旧进程；启动失败留在应用中报错，可重试。

此实现修复现有 Windows NSIS 应用内安装路径；不是 macOS/Linux 自动安装实现。
已安装旧客户端中的更新器不能靠服务器更新清单热替换，需要先安装包含此实现的
新版后，后续更新才能使用自动换源。旧版客户端仍可以使用原有应用内更新入口。

## 旧版客户端的加速兼容

服务器可为已发布版本的原安装包 URL 配置临时 HTTPS 跳转到自有加速域名
`download.laogao.xyz`。3.6.13 原有的下载库会自动跟随跳转，因此不需要先安装
新的更新器，也不需要用户更换下载链接。3.6.24 与 3.6.25 Windows 安装包均已配置此映射。
已开始传输的旧连接不会中途切换，需要结束后重新发起一次应用内更新。

以后发版时，先核对并准备对应版本的不可变加速副本及精确映射，再切换更新清单。
原安装包地址、版本、大小和哈希保持一致；加速域名加入更新器的 HTTPS 重定向
白名单。服务端配置修改须备份、校验并平滑重载，保留源站文件和回滚路径。

## 验证

- `cargo test --manifest-path src-tauri/Cargo.toml --lib update_download::tests`
  覆盖慢速、初始突发后低速、响应头/数据超时、总时长、HTTP 错误、断流、大小和
  哈希错误、HTML、无 Content-Length、重复更新保护，以及失败后不产生虚假 100%。
- `npm test --prefix frontend` 包含更新清单完整性、速度显示及状态重置回归。
- `frontend/tests/update-failover.html` 使用真实更新弹窗和隔离的 Tauri 事件桥接，
  验证慢源→自动换源→校验→安装启动提示；`?fail&dark&en&hold=backup` 可验证失败
  清理后重试及英文深色布局。该页面不会安装、退出真实应用或修改系统代理。
- 忽略的原生 live 测试把主源设为受控的低速服务器，自动切换到真实 GitHub
  3.6.24 安装包并验证 SHA-256。它只保存隔离的验证文件，不运行安装程序。
