# 参考图层改用原生图片瓦片

状态：本地开发窗口已运行，未发布。用户认为上一版矢量绘制仍然太卡，本次替换客户端渲染路径，不再在其上继续调批量参数。

## 最终路径

`现有公开 WFS → 原生后台取数与栅格化 → 透明 PNG 缓存 → WebView 图片网格`

- 四类参考要素仍由地图右侧独立面板控制；左侧下载参数和原底图列表不包含它们。
- 地图端只创建 512×512 图片瓦片。删除旧 GeoJSON / CircleMarker / 名称 Canvas / 分帧矢量构建模块，不把要素数组放进前端状态或通过预览 IPC 返回。
- 新的 `foundation_raster_tile` 只返回 PNG 数据地址和缓存、字体、空图标志。前端并发最多 3 个请求，按视口自动取图；平移复用已加载图片，过期请求取消并丢弃。
- 原生后台最多 2 个栅格任务，按瓦片范围分页取数，使用 tiny-skia 绘制几何、ttf-parser 按需读取系统中文字体轮廓。没有在安装包中嵌入中文字体，也没有新增运行时字体下载。
- 颜色、粗细、名称开关、字号及 WGS84 / 高德对齐仍有效；对齐在后台逐坐标处理。原始几何不被修改，GeoJSON 单独另存沿用原来的完整分页与安全落盘。
- 线名称采用完整要素弧长上的固定世界锚点，邻瓦片位置一致；渲染保留 128 像素缓冲，名称共用避让格。参考几何本身不套用旧的 2000 条客户端预览截断。

首个未命中的瓦片仍需取数、生成图片，不能把这段时间称为零成本。后台处理有独立限流，界面可以继续操作；缓存后复用 PNG。

## 上游图片接口验证

本轮直接读取 `https://gisserver.tianditu.gov.cn/TDTService/wms` GetCapabilities 成功，返回 236,410 字节 XML，声明上述四类图层及 EPSG:3857 支持。

但标准默认样式及自定义样式的 GetMap 实际请求均返回 HTTP 418，响应正文明确为 CloudWAF“访问被拦截”。没有伪装 Referer / Cookie 或绕过拦截，也没有把仅有能力声明当作图片服务接通。当前使用已经实测可取数的 WFS 在本机后台生成图片，不宣称已接通上游 WMS 或 WMTS 瓦片。未来上游图片接口可用时，可替换图片生产端。

## 缓存与边界

- PNG 内存缓存最多 64 项、合计 16MiB；专用磁盘缓存预算 256MiB，按批次检查与回收。只操作专属目录内符合 SHA-256 命名的缓存文件，失败不影响已经生成的图片。
- 磁盘缓存采用临时文件后原子替换；读取先验证格式与 512×512 尺寸，再解码校验。字体可用状态、样式、坐标、缩放、瓦片坐标、日期和刷新版本均参与身份，避免不同配置混图。
- 继续从 8 级开始显示。单张图片取数超过 50,000 个要素或合计 32MiB 时返回明确的“放大后重试”，不会静默截断后当作完整参考图。
- 缺少系统中文字体时仍可显示几何，并明确提示名称未显示；安装字体并重启后，缓存身份会变化。
- 地图移动时仅暂停另存入口，不把临时空视口错误显示成服务或范围异常。
